# 世界书统一管线与角色统计更新

## 修复的问题

过去不同 App 自行拼接角色提示词，导致角色已经挂载的世界书在部分场景没有进入请求，尤其是「聊天记录指定深度」条目。仅让见面和通话分别补一段逻辑，仍会让以后新 App 重复踩坑。

本次在 master `05744a82` 的修复基础上，将角色世界书的触发、宏替换、固定位置、顺序和深度装配统一到 ContextBuilder。保留 master 对发送统计中世界书小标题的处理、群聊思考块清理和世界书所有者宏替换。

## 对用户的变化

- 挂载在角色上的世界书，在已接入公共消息管线的 App 中遵循相同规则；无需为聊天、见面、通话分别重新挂载。
- 「已挂载」不等于无条件注入：停用、关键词、辅助关键词、扫描范围和概率仍然生效。常驻条目也不会突破显式停用。
- 七种位置保留原语义，同位置按 order 升序，等序保留挂载顺序。指定深度按本次实际发送消息从后往前数，保留 System / User / Assistant 角色；超出长度时放到历史起点，深度 0 放在末条之后。
- 世界书及额外系统规则不参与深度计数；关键词只扫描场景可读历史，不回读隐藏或归档记录。
- 视频通话的图片降级不会重新抽签世界书，也不会将摄像头照片错误附到世界书 User 消息上。
- 发送统计仍用于查看某一次请求；完整 JSON 是确认实际发送内容的依据。

## 给后续 App 开发者

通常只调用 `ContextBuilder.buildCharacterRequest({ char, user }, messages)`，直接发送返回的消息数组。App 提供玩法规则和实际历史，公共层负责角色及世界书。不要先调用旧文本入口再套新入口，否则会重复人设。

聊天、见面、通话需要拆分结果时用 `buildCharacterContext`；剧场、自定义预设和群聊分别使用同一模块内的布局接口。新增 App 不再直接解析世界书。测试会阻止底层处理扩散和新增旧文本入口。

接入覆盖聊天、见面、通话、群聊、剧场、跑团、Spark、学习、日程、日记、歌词、攻略本、小说、都市人生、角色间私聊、自由活动、记忆潜行、触碰/陪伴与节日活动等生成入口。

**兼容边界：**旧后台主动消息模板仍为单串协议，可包含条目正文，但不能保证独立消息角色和真实深度；少量记忆诊断/迁移/门牌任务保留文本接口。参考酒馆基础语义，并未实现完整递归、预算、Outlet 等能力。

详细契约见 [世界书管线文档](./worldbook-management.md)。

## 神经链接新增「角色统计」

入口在角色详情的「手办」之后。紫灰色分区、字数占比和可展开正文，帮助定位上下文膨胀：

1. 记忆宫殿是否启动，自动归档状态。
2. 上下文跟随宫殿水位还是用户手动范围，当前起点及用户断点；热区/缓冲只表示归档节奏。
3. 当前可读的月度总结、日度记忆数量和字数。开启的小眼睛按月份列出，可直接跳回记忆页检查；关闭小眼睛仍保留月度总结。
4. 挂载世界书的正文、字数、触发状态、位置、深度、角色和顺序；等待关键词、概率待定和停用条目不计入确定可读总量。
5. 共享消息记录按 ChatApp、DateApp、CallApp 等原始来源分组；人设、用户画像、印象、门牌、情绪底色等另列。宫殿上次召回作为缓存快照单独展示。

这是本地可读范围诊断，**不是每个 App 下一次请求的精确复刻**。App 可继续筛选消息或添加玩法规则；未写入共享记录的独立会话不在统计范围内。页面不调用模型、不抽取记忆、不消耗概率随机数，也不修改角色配置。

字符数与 Token 分开显示。Token 醒目标注「估计值，非真实用量」，按简单本地规则估算，实际以 API usage 为准。模型间没有通用中文比例或保证的大小顺序；说明中仅引用 DeepSeek 官方中文字符约 ×0.6 的例子，并提供各家官方计数文档链接，不将其推广为所有国产模型。

详细统计口径见 [角色统计文档](./character-statistics.md)。

## 验证

公共管线测试覆盖七种位置、深度、角色、关键词、概率、群聊所有者和去重；请求测试覆盖聊天、见面、剧场和视频通话降级。角色统计测试覆盖小眼睛/月度总结、中文日期、概率只读预览、范围水位、来源分类、宫殿残留过滤和 Unicode 计数。

角色统计手机端已用真实 React / IndexedDB 测试页面验证布局、刷新、正文展开和跳转记忆页。相关修改文件 TypeScript 诊断为零；全仓已有类型问题不作为本次通过声明。
