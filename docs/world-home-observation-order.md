# 家园观测顺序与进度

`world_episodes.createdAt` 是观测完成时间；`round` 是剧情/手机消息引用使用的轮次。旧世界状态被界面快照覆盖时，可能出现两个相同 round、realClock 回退，导致下一轮再次演绎上一时段。

- `DB.getWorldEpisodes` 先按完成时间排列全部记录，再截取最近若干条。主界面、角色房屋和手机都使用返回的第一条作为最新观测。
- 读取时计算 `observationNumber` 作为纪事显示序号，兼容已存在的重复轮次。该字段不落库，不改写历史 round、消息关联或剧情内容。
- 引擎在占用运行锁后重新读取世界及最近历史，通过 `recoverWorldProgress` 恢复被覆盖的计数。现实模式计数落后时，使用历史的明确日期/时段标签恢复 realClock；正常计数下不干预用户换时区后的时钟调整。
- 现实模式的凌晨属于前一剧情日的 seg=3，但标签显示次日日期。不要把观测完成时间强行当作剧情时间：补演、慢请求等都可能让二者不同。
- 界面编辑用 `DB.updateWorld` 在事务中对最新世界打补丁；世界设置只保存相对打开编辑器时发生变化的字段，避免旧草稿覆盖后台推进的 storyClock/realClock。

已有错误剧情标签无法仅凭完成时间可靠判断原本应该演哪一段，因此保留；恢复的是显示顺序、显示编号和后续观测进度，不重新调用 API 或重写历史剧情。

回归测试：`utils/worldHome/episodeOrder.test.ts`，覆盖跨午夜重复轮次、下一凌晨时段、设置保存和已删除世界不复活。
